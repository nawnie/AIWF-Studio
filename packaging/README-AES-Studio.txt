AES Studio preview

This is an unsigned, per-user x64 preview. The application shell targets 64-bit Windows 10 version 2004 (build 19041) or newer; Windows on ARM has not been tested. For the bundled CUDA 13.2 image engine, NVIDIA's supported Windows 10 version is 22H2; see its CUDA installation guide for supported Windows 11 versions. The bundled engine requires a supported NVIDIA GPU, a compatible NVIDIA driver, and a CPU supporting AVX2, FMA, F16C and BMI2. CUDA 13 minor-version compatibility requires driver 580 or newer, subject to NVIDIA's feature limitations. These requirements do not guarantee a particular model will fit or run. Other hardware requires manual runtime setup; Python inference dependencies are not included.

Studio installs alongside the older AIWF Studio app and keeps its separate profile in %LOCALAPPDATA%\Programs\AES Studio Data. Models are not included.

Run AES Studio Setup, choose the recommended C++ and optional Python engines or the manual C++-only choice, select an install folder, and optionally enter Hugging Face and/or Civitai keys. Python inference packages require separate manual setup. Keys are stored in Windows Credential Manager for this Windows account, are not validated during setup, and can be changed or removed from Configure Studio. No key is needed for public models.

When you reinstall interactively, the backend you select replaces the saved AES backend selection; the rest of the AES profile is preserved. A silent reinstall keeps an existing backend selection because no interactive choice was made.

AES keeps its folder choices and project ledger in the separate AES Studio Data profile, so those choices remain available when you uninstall and reinstall. If you used an earlier AES preview that stored launch.json and _local\unified-projects inside its installation folder, migrate those files into the AES Studio Data profile before removing that old folder; preserve both copies if there is a conflict.

First launch scans this PC and suggests a starting model when NVIDIA telemetry reports at least 8 GiB of VRAM, compute capability 7.5 or later, a CUDA 13 compatible driver, and Windows reports at least 12 GiB of system memory. This conservative memory threshold is a starting heuristic, not a guarantee of fit. If any requirement cannot be determined, it does not make an automatic recommendation for the bundled engine. If NVIDIA telemetry is unavailable, Windows-reported graphics adapters and their dedicated and shared memory are shown; those figures do not establish CUDA compatibility. Review the model source and license. The optional checkpoint downloader supports Hugging Face owner/model and file paths or Civitai numeric model version IDs, for .safetensors, .ckpt, .pt, .pth and .gguf files. When the PC qualifies for the SDXL suggestion, the Use suggested SDXL Base 1.0 button fills in its provider and file details; otherwise enter model details manually. It uses a saved provider key when present and asks before downloading. Downloads go to the saved Image checkpoints folder, can be several gigabytes, and do not overwrite existing files. The suggested official SDXL file is checked against its published SHA-256; other safetensors files receive a structural check, and GGUF files only a shallow header check. Legacy .ckpt, .pt and .pth files are not structurally verified and can contain code that executes when loaded. Use trusted model sources. None of these checks proves model compatibility or safety.

The bundled C++ image workflow currently offers recognized SD 1.5 and SDXL single-file checkpoints in .safetensors, .ckpt, .pt, .pth or .gguf form; recognition may use the filename, and finding a file does not verify that it will run or has every required component. Other architectures and separate component files are not yet supported by this C++ workflow even if the underlying engine supports them. The optional Python engine can also discover compatible Diffusers model folders and supported checkpoints after its inference packages are installed. Place existing models in the configured model folders and refresh readiness. Setup checks files without loading weights or testing generation.

The Create page also offers experimental local ComfyUI workflows for Qwen Image 2.1 editing, MOSS Image, Wan 2.2 5B image-to-video, and LTX 2.5 GGUF image-to-video. Start your own ComfyUI first, open More models and video, choose the local port, and use Find local model files. Choose matching components yourself; discovery does not establish compatibility. ComfyUI, its model files, and any required custom nodes are not included or installed by AES Studio. Missing node names are shown in the app. The MOSS template uses ComfyUI's standard MOSS-capable loaders and needs a compatible MOSS model, Qwen 3.5 text encoder and FLUX.2-compatible VAE. The Qwen template needs the Qwen Image 2.1 nodes, and the LTX GGUF template requires the GGUF loader and LTX video/audio nodes. The video workflows currently make short 17-frame previews; dimensions, model family and GGUF requirements are specific to each template. A selected reference image is copied into ComfyUI's input folder, while the result is copied into AES Studio's output folder. AES can cancel a queued job; stop a running job in ComfyUI. Closing AES does not stop an already queued ComfyUI job.

Uninstall removes unchanged installer-owned files. Your models, outputs, settings, credentials, and modified files are kept. To remove a provider key, use Configure Studio before uninstalling, or delete the AESStudio.HuggingFace or AESStudio.Civitai entry in Windows Credential Manager. To reinstall, uninstall the existing preview first, then choose a new empty installation folder if the original folder still contains retained files. The separate AES Studio Data folder is preserved.

Setup has been exercised in Windows Sandbox, and an SD 1.5 model was run on the development PC. Creative model templates have been run with that PC's existing ComfyUI and files. Other clean PCs, model combinations, real gated provider credentials, and the optional Python inference environment still need testing. This is an unsigned preview, not a finished production release.

Manual Python backend: close AES Studio, install uv from its official source, and run scripts\provision_python_backend.ps1 from the installation root as documented by that script. This can download several gigabytes. The native inference lock does not include the legacy Gradio web interface. If an older shared environment already contains Gradio, use a fresh AES installation rather than removing packages from that environment. The optional lock still contains dependencies with reported security advisories, including Transformers and Jupyter components; review those before production use. The bundled C++ backend does not require this step.

App-local Microsoft Visual C++ redistributable libraries and the included NVIDIA CUDA libraries have their notices in the licenses and dependencies directories. App-local Visual C++ libraries do not receive shared runtime security updates; update the application when a new build is supplied.
